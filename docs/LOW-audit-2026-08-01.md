## 1. Two live defects found

### 1a. A preliminary NWS report froze a wrong settled value — and mis-graded a bet

NWS normally issues LAX's climate report ~01:30 local the next day, after the
climate day (01:00→01:00 local) closes. On 2026-07-30 it issued one at **18:29
local the same day**. `backfill._yesterday_cli` stopped at `if have: return 0`,
so that preliminary row was frozen forever.

It said `low 70 at 5:52 AM`. The day went on to bottom at **67 at 11:59 PM** — an
evening minimum. The final product (202607311139) carries 67.

Consequences, all now corrected:

- `app_bets` KLAX low 2026-07-30 bucket `≥69` was graded **WON**. At 67 it LOST.
  **The placed record is 2W–4L, not the 3W–3L reported earlier today**, and
  "all three bets that bought a contract lost" is also correct.
- The morning audit "verified" `app_bets.actual` against `cli_reports` — both
  read the same corrupted row, so it proved nothing.
- The live LOW scorecard read 78.6 % / MAE 0.49; corrected it is **71.4 % / 0.68**.

Scope: **1 of 1,144** stored station-days. A race, not systemic rot — but it
lands hardest on evening-minimum days, which are ~35 % of KLAX lows.

**Fixed:** `backfill.cli_row_is_final()` trusts a row only if its product was
issued after that station's climate day closed (KLAX 08:00Z, KMIA 05:00Z,
derived not hardcoded), else re-fetches. Fails toward freshness.
`tests/test_cli_preliminary.py`.

### 1b. The preflight was silently applying stale thresholds — now retired

`preflight.BANDS` is keyed `(station, metric)` with **no hour**, while `grade()`
reads the commit hour from `gating.MIN_DECISION_HOUR`. When the hour moved h4→h6
this morning, h4 thresholds were applied to h6 readings and the dashboard kept
printing CLEAR/FAIR/AVOID. Nothing failed; the verdict just stopped meaning
anything.

Re-measured at h6:

| | n | stated | hit | shortfall |
|---|---|---|---|---|
| flagged (gap > 1.19) | 287 | 65.1 % | 65.3 % | −0.3 % |
| clean (gap ≤ 1.19) | 287 | 69.6 % | 70.6 % | −1.0 % |

Δshortfall **+0.7 %, CI [−5.7 %, +6.8 %] → DO NOT SHIP.** At h4 it was +9.3 %
[+1.6, +15.9]. **Both strata now under-state**, so there is no
confidently-wrong regime left to flag — the same reason no HIGH preflight was
ever buildable. The later hour *is* the preflight.

`BANDS` is now empty, pinned by a test. Mechanism coverage (commit-hour
preference, provisional labelling, cross-station isolation) survives via an
injected synthetic table.

## 3. Backtest — the blend-beats-model finding is KLAX-ONLY, not a LOW property

`highcast backtest --metric low`, walk-forward, n = 1,670:

| day-ahead | n | MAE | CRPS | cov90 |
|---|---|---|---|---|
| **KLAX** ML (hybrid) | 1670 | 1.374 | 0.956 | 0.854 |
| **KLAX** plain blend | 1670 | **1.319** | **0.929** | 0.916 |
| **KMIA** ML (hybrid) | 2026 | **1.604** | **1.162** | 0.865 |
| **KMIA** plain blend | 2026 | 1.670 | 1.189 | 0.923 |

**The two stations disagree, and that refines the known result.** At KLAX the
plain blend wins by 0.055 °F MAE — reproducing `model_vs_blend`'s conclusion. At
KMIA the trained model wins by 0.067 °F. So "the day-ahead model does not earn
its complexity on the LOW" is a **KLAX-specific** finding, not a property of the
LOW metric, and should stop being stated the general way.

Neither margin is large and this backtest reports no confidence interval, so
treat both as directional. The one consistent pattern across both stations is
DISPERSION: the ML model is under-dispersed (cov90 0.854 / 0.865 against a
nominal 0.90) while the blend is over-dispersed (0.916 / 0.923). Same shape the
intraday tails already show.

(`mae_nws 13.0` at KMIA is computed on n=2 and is noise; ignore it.)

**It does not change what you trade.** The LOW desk reads the **intraday
nowcast**, whose MAE at the commit hour is **0.727 (KLAX)** and **1.013 (KMIA)** —
roughly twice as good as either day-ahead number. The day-ahead matters only for
the evening preview.

## 4. Walkthrough — KLAX LOW, 2026-07-30 (a real, and instructive, day)

```
commit h6 = 21:00 Manila
1. MODEL      parity 0: 68–69 @ 62.1%     parity 1: 69–70 @ 90.7%
              point 69.16 °F
2. OBSERVED   running min 66.82–67.02 °F
3. GATES      ok=False   refusals=('unmeasured_band',)
4. CALIBRATION raw 90.7% -> None  (REFUSE: ≥80% band unmeasured, n=13)
5. SETTLED    67 °F      -> model erred +2.16 °F
```

Three things this shows:

1. **The gates worked.** The model's 90.7 % read sat above KLAX LOW's highest
   measured band, so the system refused. Had it acted, it would have lost.
2. **The parity coin-flip is not academic** — 62.1 % vs 90.7 % on the same day,
   the same data, depending only on where Kalshi centres the ladder.
3. **This was an evening-minimum day**, and it is the day that exposed the
   preliminary-CLI bug. The two biggest LOW risks showed up together.
